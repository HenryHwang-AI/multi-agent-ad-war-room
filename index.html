      产品判断

      这页不是模型秀。它把投放前的准备收成一条看得见的状态机，用来讲清楚多 Agent 到底买到了什么，以及人该站在哪一步。

      角色按职责切开

      四个角色吃不同的输入，也拒绝做别人的事。这样切，是为了失败时知道该重跑谁，而不是为了把一个提示词拆成四段语气。

      • 洞察官只产出标了「测量」或「推断」的假设，不写口号。
      • 创意官只基于这些假设写角度，不给自己发合规通行证。
      • 合规官只引用原句并判定，不改预算。
      • 分析官只设计可以停下来的实验，不顺手加码承诺。

      编排器的产出是状态迁移和账本，字数为零。洞察卡片一旦锁定，回环就不会再为它付钱。

      同一批风险，两种处置

      合规官看到的命中句是同一批，写在每条简报的初稿里。默认阈值把它们记成观察项，任务包改用安全句，流水线不回环。打开「注入合规失败」之后，阈值升成驳回：创意官重做，人再看一次，合规再审一次。事实没有变，变的是策略。

      功效、金融、医疗邻近类目更适合把严格处置做成默认，而不是演示开关。澄光和轨迹这两条简报就是这个原因被标成「适合演示回环」。

      成本和延迟买的是什么

      顺利路径会多花 token，也会更慢。关键路径是串行的：创意依赖洞察，合规依赖已经批准的创意，实验依赖合规结论。一个角色内部的工具调用可以并行，演示里仍让它们先后出现，方便看清。

      路径 模拟 token 模型墙钟 演示费用 人工闸门 可单点重跑

      人工在闸门前的停留单独计时，不算进模型墙钟。人的时间才是这条链路真正的关键路径，所以闸门只有一道，问的是方向，不是标点。

      闸门为什么在创意和合规之间

      这一步的判断主要是品味、品牌和任务是否匹配，不该由模型拍板。合规审查会花下一段 token，应该拿去审已经值得审的方向。

      闸门不放在最后，是为了避免人读完一篇混好的长文才发现方向就错了。也不放在洞察之前，因为没有材料的审批只是直觉。生产环境还可以在合规通过之后、预算释放之前加第二道法务闸。这个演示故意只做产品闸，避免看起来像自动投放。

      要求修改会把备注写成下一张创意卡片的约束，而不是丢进越来越长的聊天。批准写进轨迹，带任务编号，方便事后回答是谁在什么状态下放行的。驳回不会请人给一份已知有问题的稿子盖章，人看到的下一张卡片已经是修订稿。

      单 Agent 什么时候够用

      头脑风暴、内部草稿、没有外部投放风险的时候，一个模型更快也更便宜。句子一旦会进广告账户，混写的代价是：你无法只驳回其中一句，也证明不了洞察没有被口号污染。下面是当前简报如果一次生成，会长什么样。

      故意不交给系统的事

      • 不登录投放账户，不创建计划，不改出价。
      • 不把合规结论当成法律意见。规则是为演示抽象的。
      • 不释放预算。
      • 不生成真实用户画像。简报里的样本都是虚构的。

      如果进入生产，还要补什么

      • 每张卡片的结构校验，不合格就不能迁移状态。
      • 从历史驳回整理评估集，看合规官会不会放过已知坏句。
      • 编排器幂等，避免闸门被双击造成两次送审。
      • 权限：谁能批准，敏感类目要不要双人。
      • 观测：步骤耗时、驳回率、人在闸门的等待，以及任务包导出后有没有被改。

      这些没有做进演示。演示要证明的是状态机和闸门，不是一个投放平台。
